# EDA Findings — crm-experiment-lab (`data/experiment_sample.csv`)

**Дата:** 2026-10-13
**Полный отчёт:** `reports/eda/eda-crm-experiment-2026-10-13.md`

## Датасет вкратце

`data/experiment_sample.csv` содержит 300 строк, одна строка = **user-day** (юзер × день).
Период: `day` 0..19 (целочисленный индекс, не календарь); 15 юзеров, полная сетка 15 × 20.
Качество данных в целом **хорошее по структуре** (0 пропусков, 0 дубликатов, полная сетка),
но **узкое по содержанию**: нет колонки группы/сегмента, `unsubscribed` — константа, всего
16 покупок. README-заголовки воспроизводятся из симулятора (15/15), но не из фикстура.

## Топ проблем качества

### Проблема 1: фикстур не проверяет README-заголовки (нет группы)
- **Что:** `experiment_sample.csv` не содержит `group` (test/control/gcg) и `segment` — уплафт, net-of-unsub и SRM из него невычислимы.
- **Влияние:** читатель README не может воспроизвести заявленные +0.9968 / +50.5 из единственного CSV на диске.
- **Действие:** пометить CSV как «schema example, not a pipeline artifact»; либо закоммитить артефакт `simulate(...)`.
- **Владелец:** аналитик / владелец репозитория.

### Проблема 2: `purchase_amount` экстремально скошена
- **Что:** skew = 7.79; 284/300 строк = 0; среди 16 оплат медиана 324.84, mean 503.03, max 1693.39.
- **Влияние:** среднее по сумме смещено вверх; сравнение групп по mean-AOV даст ложные различия.
- **Действие:** докладывать медиану/p95 и разделять «доля покупок» × «AOV среди оплативших».
- **Владелец:** аналитик.

### Проблема 3: `unsubscribed` вырождена в константу
- **Что:** все 300 строк = False (профилировщик помечает [WARN]).
- **Влияние:** net-of-unsubscribe по фикстуру = 0; сигнал churn не наблюдаем.
- **Действие:** не считать unsubscribe-метрики по фикстуру; брать из полного прогона (там Δ = +0.1623).
- **Владелец:** аналитик / дата-инженер.

### Проблема 4: `sessions` не связана с покупкой в фикстуре
- **Что:** r(sessions, purchased) = −0.01; ставка по бакетам не монотонна.
- **Влияние:** фикстур не демонстрирует exposure-механизм DGP (test-юзеры +1 сессия в день показа).
- **Действие:** измерить связь на полном 20k-прогоне; не делать выводов о драйвере из фикстура.
- **Владелец:** аналитик.

### Проблема 5: фикстур не регенерируется из симулятора
- **Что:** 0 совпадений `simulate(SimulationConfig(n_users=15, n_days=20, seed=s))` с CSV на seeds 0..1999.
- **Влияние:** фикстур не является воспроизводимым артефактом текущего кода.
- **Действие:** задокументировать происхождение или перегенерировать из симулятора.
- **Владелец:** владелец репозитория.

## Что в порядке

- 0 пропусков во всех 6 колонках.
- 0 полных дубликатов и 0 дубликатов по ключу `(user_id, day)`; сетка полная (300 = 15 × 20).
- `user_id` (0..14) и `day` (0..19) непрерывны, будущих значений нет.
- `purchased=True` ⟺ `purchase_amount>0` (0 расхождений); нет покупок без сессии.
- Суммы по неделям сходятся с агрегатом: 2870.60 + 2561.24 + 2616.57 = 8048.41.
- `sessions` в диапазоне 0..6, целые, без выбросов (IQR 0%).
- README truth check: 15/15 проверяемых заголовков → REPRODUCED из симулятора (seed 42).
